# Java 后端面试题库与参考答案

> 本文档用于 Career Orbit 知识库演示。包含 Java 基础、集合、并发、JVM、Spring、MySQL、Redis 与场景设计题,每题附参考答案与评分要点。上传后可按技术方向、难度检索。

## 一、Java 基础

### 1. `==` 和 `equals()` 的区别?(基础)

参考答案: `==` 对基本类型比较值,对引用类型比较内存地址(是否同一个对象)。`equals()` 是 Object 的方法,默认实现就是 `==`,但 String、Integer 等类重写后比较的是内容。重写 `equals()` 必须同时重写 `hashCode()`,否则放入 HashMap/HashSet 会出现"相等对象散列到不同桶"导致去重失败。

评分要点: 能说清值/地址/内容三层区别;能指出 equals 与 hashCode 的契约关系。

### 2. String、StringBuilder、StringBuffer 的区别?(基础)

参考答案: String 不可变,每次拼接产生新对象;StringBuilder 可变、非线程安全、性能最好;StringBuffer 可变、方法加 synchronized 线程安全但更慢。循环内拼接字符串应使用 StringBuilder,避免在循环里用 `+` 造成大量临时对象。

评分要点: 答出不可变与线程安全两点;提到编译器会把简单 `+` 优化为 StringBuilder。

### 3. 接口和抽象类的区别?如何选择?(基础)

参考答案: 抽象类可有成员变量、构造器、普通方法,单继承;接口是行为契约,可多实现,Java 8 后可有 default/static 方法但不能有实例字段。选择原则:描述"是什么"用抽象类,描述"能做什么"用接口。

评分要点: 说出单继承 vs 多实现;能结合实际场景给选择理由。

## 二、集合

### 4. HashMap 的底层原理?(进阶)

参考答案: JDK8 起是「数组 + 链表 + 红黑树」。put 时先算 key 的 hash(高 16 位异或低 16 位再与 (n-1) 取模定位桶),桶为空直接放;有值则比较 hash 与 equals,相同则覆盖,不同则挂链表;链表长度达 8 且数组长度 ≥ 64 时转红黑树。默认容量 16,负载因子 0.75,元素数超过阈值扩容为 2 倍,扩容时重新分配(JDK8 用高低位链表优化,避免重新计算 hash)。非线程安全。

评分要点: 说清数组+链表+红黑树、扩容机制、hash 扰动函数;提到线程安全问题。

### 5. ConcurrentHashMap 如何保证线程安全?(进阶)

参考答案: JDK7 用分段锁 Segment;JDK8 改为 CAS + synchronized,只锁单个桶的头节点,并发度更高。扩容时支持多线程协助迁移,size 用 baseCount + CounterCell 分散计数。读操作基本无锁(volatile 保证可见性)。

评分要点: 区分 JDK7 分段锁与 JDK8 桶级锁;能指出读不加锁的原因。

### 6. ArrayList 和 LinkedList 的区别?(基础)

参考答案: ArrayList 底层数组,随机访问 O(1),中间插入删除需搬移元素 O(n),扩容 1.5 倍;LinkedList 底层双向链表,随机访问 O(n),头尾增删 O(1),内存开销更大。绝大多数场景选 ArrayList,除非频繁在头部插入。

评分要点: 说清数据结构与复杂度差异;给出选型建议。

## 三、并发编程

### 7. volatile 的作用和原理?(进阶)

参考答案: 保证可见性和有序性,不保证原子性。写操作后立即刷回主内存并使其他线程缓存失效;通过内存屏障禁止指令重排序。典型用途:状态标志位、双重检查锁定的单例。`i++` 这类复合操作加 volatile 仍不安全,需用 synchronized 或 AtomicInteger。

评分要点: 强调"不保证原子性";能举例双重检查锁定。

### 8. synchronized 的锁升级过程?(高级)

参考答案: 无锁 → 偏向锁 → 轻量级锁(CAS 自旋)→ 重量级锁(操作系统互斥量)。偏向锁记录线程 ID,同一线程再进入无需竞争;有竞争升级为轻量级锁自旋;自旋失败或竞争激烈升级为重量级锁,线程进入阻塞。锁只能升级不能降级。JDK15 后偏向锁默认关闭并逐步废弃。

评分要点: 说出四种状态与升级路径;知道偏向锁的存废现状。

### 9. 线程池的核心参数和执行流程?(进阶)

参考答案: 核心参数有 corePoolSize、maximumPoolSize、keepAliveTime、workQueue、threadFactory、handler。执行流程:核心线程未满则创建核心线程;满了入队;队列满且线程数未达最大值则创建非核心线程;再满则触发拒绝策略(AbortPolicy 抛异常、CallerRunsPolicy 调用者执行、DiscardPolicy 丢弃、DiscardOldestPolicy 丢最旧)。生产建议自定义 ThreadFactory 命名、用有界队列。

评分要点: 四步流程完整;能说多种拒绝策略;提到队列必须有界。

### 10. ThreadLocal 会造成内存泄漏吗?(高级)

参考答案: 会。ThreadLocalMap 的 key 是弱引用(ThreadLocal),value 是强引用。key 被回收后 value 仍被 Entry 强引用,线程不结束(如线程池复用线程)则 value 无法回收。解决:用完务必 `remove()`,推荐 try-finally 中调用。

评分要点: 说清弱引用 key / 强引用 value 的机制;强调 remove。

## 四、JVM

### 11. JVM 运行时内存区域?(进阶)

参考答案: 线程私有:程序计数器、虚拟机栈、本地方法栈;线程共享:堆、方法区(JDK8 起为元空间 Metaspace,使用本地内存)。堆是 GC 主战场,分新生代(Eden + 两个 Survivor)和老年代。

评分要点: 区分私有/共享;说明 JDK8 元空间变化。

### 12. 常见的垃圾回收算法和回收器?(高级)

参考答案: 算法有标记-清除(碎片多)、标记-复制(适合新生代)、标记-整理(适合老年代)。回收器:G1 按 Region 划分、可预测停顿,主流默认;ZGC 和 Shenandoah 追求超低停顿,适合大堆。

评分要点: 算法与回收器对应;知道 G1 是当前主流。

## 五、Spring

### 13. Spring IOC 和 DI 是什么?(基础)

参考答案: IOC(控制反转)把对象的创建和依赖管理交给容器;DI(依赖注入)是 IOC 的实现方式,通过构造器、setter 或字段注入依赖。好处是解耦、便于测试与替换实现。推荐构造器注入,可保证依赖不可变且非空。

评分要点: 说清 IOC 是思想、DI 是手段;提到构造器注入优点。

### 14. Spring AOP 的实现原理?(进阶)

参考答案: 基于动态代理。目标类实现接口时用 JDK 动态代理(基于接口),无接口时用 CGLIB 生成子类代理。Spring Boot 2.x 后默认统一使用 CGLIB。切面通知类型:Before、After、AfterReturning、AfterThrowing、Around。

评分要点: 区分 JDK 与 CGLIB;说明默认策略。

### 15. Spring 事务在哪些情况下会失效?(高级)

参考答案: 常见失效场景:方法非 public;同类内部方法自调用(绕过代理);异常被 catch 未抛出;抛出的是受检异常而默认只回滚 RuntimeException;数据库引擎不支持事务(如 MyISAM);多线程中调用。解决:自调用可注入自身代理或拆分方法,必要时指定 rollbackFor。

评分要点: 至少说出自调用、异常类型、非 public 三类;能给出解决思路。

## 六、MySQL

### 16. 为什么用 B+ 树做索引?(进阶)

参考答案: B+ 树非叶子节点只存键、不存数据,单页能放更多键,树更矮,磁盘 IO 更少;叶子节点用链表相连,范围查询和排序高效。相比 B 树,查询性能稳定(每次都到叶子);相比哈希索引,支持范围查询。

评分要点: 从树高、IO 次数、范围查询三方面对比。

### 17. 事务的隔离级别和各自解决的问题?(进阶)

参考答案: 读未提交(脏读)、读已提交(解决脏读,有不可重复读)、可重复读(MySQL 默认,解决不可重复读,InnoDB 靠 MVCC + 间隙锁基本解决幻读)、串行化(全解决,性能最差)。

评分要点: 四级与对应问题配对正确;提到 MySQL 默认是可重复读。

### 18. 慢查询如何优化?(高级)

参考答案: 用 explain 看执行计划(type、key、rows、Extra);为 where/order by/join 字段建合适索引并遵循最左前缀;避免索引失效(函数、隐式类型转换、前导模糊、or);减少回表(覆盖索引);分页大偏移用书签或延迟关联;必要时拆分大表、读写分离、加缓存。

评分要点: 能落地 explain 与索引优化;不空谈。

## 七、Redis

### 19. 缓存穿透、击穿、雪崩的区别与对策?(进阶)

参考答案: 穿透是查询不存在的数据打到库,对策:布隆过滤器、缓存空值。击穿是热点 key 过期瞬间大量请求打库,对策:互斥锁重建、热点永不过期、逻辑过期。雪崩是大量 key 同时失效或 Redis 宕机,对策:过期时间加随机、多级缓存、集群高可用、限流降级。

评分要点: 三者定义清晰区分;对策具体。

### 20. Redis 分布式锁怎么实现?(高级)

参考答案: 用 `SET key value NX PX ttl` 加锁,value 存唯一标识;释放锁用 Lua 脚本先校验标识再删除,防止误删他人的锁。需考虑锁续期(看门狗)与可重入。生产也可用 Redisson。

评分要点: 强调 NX、过期时间、Lua 校验释放;知道续期问题。

## 八、场景设计

### 21. 设计一个接口幂等方案?(高级)

参考答案: 常见手段:唯一业务号 + 数据库唯一索引;token 机制(先申请一次性的幂等 token,提交时校验并删除);状态机(只允许特定状态流转);乐观锁版本号;分布式锁。按业务强度选择,尽量用数据库唯一约束兜底。

评分要点: 给出至少两种方案并说明适用场景;强调唯一索引兜底。

### 22. 短链系统如何设计?(高级)

参考答案: 发号器(自增、雪花、号段)+ 进制转换(Base62)生成短码,映射存 Redis + MySQL,读多写少可加本地缓存;跳转用 302;考虑防冲突、防刷、统计点击数(异步)。

评分要点: 讲清短码生成、存储、跳转、扩展性。
